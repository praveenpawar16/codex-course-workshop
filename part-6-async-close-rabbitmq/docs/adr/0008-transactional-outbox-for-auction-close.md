# Transactional outbox for auction close

Closing an Auction must record the durable outcome and enqueue the downstream notify work without a dual-write race against RabbitMQ. The Close Worker, in one PostgreSQL transaction, marks the Auction Closed (Winner + Winning amount, or Unsold), inserts the outbox event for that close, and only afterward publishes to RabbitMQ—marking the outbox row published only after the broker confirms the publish. Consumers process idempotently and rely on database uniqueness constraints so duplicate deliveries cannot create duplicate Close notifications. Rejected for this part: publishing to RabbitMQ inside the same DB transaction (not supported), fire-and-forget publish without an outbox, and elaborate dead-letter / retry infrastructure (deferred).
