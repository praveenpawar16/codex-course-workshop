# Adopt Drizzle ORM for Part 6 data access

Issue [#1](https://github.com/praveenpawar16/codex-course-workshop/issues/1) requires removing raw application SQL in favor of Drizzle across Part 6 services (API, close worker, notification path). We map tables in `server/src/db/schema.ts` and access them via `drizzle-orm/node-postgres`, while keeping ordered SQL migrations for DDL. Concurrency protection stays explicit: bid acceptance uses `FOR UPDATE` through Drizzle’s `.for('update')`, and close claiming uses `.for('update', { skipLocked: true })` in the same transaction as the outbox insert. This supersedes [ADR 0009](./0009-keep-plain-pg-over-orm.md) for Part 6. Rejected: leaving raw `pool.query` strings in application code, and rewriting DDL into drizzle-kit push for this slice (migrations remain the source of schema truth).
